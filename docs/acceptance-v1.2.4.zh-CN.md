# v1.2.4 格式验收

环境：Windows、本机已登录的 Chrome for Testing 143、未打包的 v1.2.4 扩展、真实 ChatGPT 会话与飞书网页版测试文档。私有会话、文档地址、截图、登录数据和回读材料仅保存在本地忽略目录，不进入仓库或安装包。

## 问题与修复

| 观察到的问题 | 修复后的行为 |
| --- | --- |
| 新版组件的强调文字失去粗体 | 将 `data-d-default-strong` 转为语义粗体，并显式声明导入样式 |
| 原生表格各列退回窄列 | 测量源列宽，生成约 720px 总宽的 colgroup，保留比例和合并单元格 |
| 计算器丢失单选项、滑块和金额，摘要金额进入目录 | 独立组件整块保存为静态图片，保留标题、参数、结果及说明 |
| 百分比尺寸 SVG 变成低清小图 | 按显示尺寸明确栅格化尺寸，大图提高采样，小图标保持自然尺寸 |
| 搜索卡片配图无法读取 | 将 `images.openai.com` 加入固定素材域名权限 |
| 正文可点击词条被当作工具按钮删除 | 保留内联词条文字，继续移除工具按钮 |
| 独立有序列表接续上一列表编号 | 默认明确设置 `start="1"`，保留显式自定义起点；连续编号段落恢复为独立列表 |
| 图标加说明正文被误判为图形，长行可能裁切 | 说明正文保留为可编辑文字，不整行截图 |

## 真实网站检查

完整滚动浏览源会话的 5 条用户消息、5 条回复及原飞书文档，逐屏检查文字、表格、卡片、图片和代码块。修复后从扩展重新生成完整离线 HTML，通过文件内“复制全部到飞书”按钮和浏览器 Ctrl+V 粘贴到专用测试文档，再以页面截图与飞书内容回读交叉核对。

同时检查真实 ChatGPT 回复下的原生复制按钮路径，以及两个独立有序列表从 1 重新编号的粘贴夹具。原会话没有发送测试消息，原飞书文档没有覆盖。

最终整段导出包含 10 条消息，导出警告为零。飞书回读确认 29 张原生表格、36 个图片块（21 张主图/卡片、15 个小图标），原先 4 个误入标题的金额均不再出现在目录中；独立的三项编号恢复为 1、2、3。首张 SVG 图片由原文档的 245×150 提升到 1486×908。原生复制按钮单条验收回读为 4 张原生表格、10 个图片块，强调文字与计算卡片保留。

## 边界

- 交互卡片在飞书中是当前状态的静态图片，不能继续调参；修改参数后需重新复制。
- 网页没有提供实际 href 的弹窗词条只保留文字，不能凭空生成链接。
- 字体、段落间距和飞书编辑器显示由目标网站控制；本次验收不承诺像素级一致。
- 已下载的旧 HTML 不会自动更新，需要重新导出。
- 本次发布 GitHub Release，不自动上传 Chrome 应用商店，也不替换 v1.2.2 的历史商店审核包。
